# QR Code Generator v1.0 — Test Report & Product Listing

**File:** `index.html` (41.6 KB — limit 150 KB) · single file, all CSS/JS inline, zero external assets, zero network calls, no localStorage, no service workers, no permissions, no parent-window access. Safe for the sandboxed Wix iframe. The QR encoder is written from the ISO 18004 specification inside the page (Reed–Solomon error correction over GF(256), block interleaving, mask evaluation) — no libraries, no backend, no API keys. No feature requires a server.

## What it does — the user decides the fields
A content-type picker offers 8 kinds of code, each with its own field set:
- **Text** — free text
- **Website** — URL (https:// added automatically if omitted)
- **Wi-Fi** — SSID, security (WPA/WEP/none), password, hidden-network flag → `WIFI:` payload with spec escaping
- **Contact card** — name, organisation, title, phone, email, website, street, city, postal code, country, note → vCard 3.0
- **Email** — recipient, subject, message → `mailto:`
- **SMS** — number + message → `SMSTO:` · **Phone** — number → `tel:` · **Location** — latitude/longitude → `geo:`
Every field is validated (required fields, email/phone formats, coordinate ranges, URL parsing), with the error shown under the exact field. A live preview shows the exact encoded content and byte count as the user types. Output: QR versions 1–20, error-correction L/M/Q/H, PNG download at 256–2048 px and resolution-independent SVG.

## Automated tests — all passed
- **Payload builders & validation (31/31, Node, run against the shipped code):** URL normalisation and rejection of malformed addresses; Wi-Fi payload escaping (`;` `,` `"` `:` `\`), no-password and hidden variants, required-field errors; vCard structure (N/FN ordering, ORG/TEL/EMAIL lines, phone cleaning, invalid-email rejection); mailto percent-encoding; SMSTO/tel payloads; geo range and non-numeric rejection; capacity guard (over-long content returns a controlled failure); SVG output shape.
- **Scannability proof (15/15):** matrices generated by the shipped encoder — versions 1, 2, 3, 6, 10, 13, 17 and 20 across EC levels L/M/Q/H, including Wi-Fi, vCard, geo, mailto and multi-byte UTF-8 (Arabic + emoji) payloads — were rendered to images and **decoded by ZXing, the industry-standard barcode engine; every one decoded back to the exact original content.**
- **Version selection:** agreed with the segno reference encoder on all 60 comparison cases. (Note: segno's matrices themselves differ from the spec by one padding byte — its `write_padding_bits` adds a full zero codeword when the stream is already byte-aligned. This encoder follows ISO 18004 §7.4.10, as do ZXing and Nayuki; ZXing's decode results above are the ground truth.)
- Full inline scripts pass a JavaScript syntax check; file size verified at 41.6 KB.

## Manual testing checklist
- [ ] Open `index.html` in Chrome/Edge — loads cleanly, no console errors
- [ ] Text type: type a sentence → Generate → scan with your phone → the exact text appears
- [ ] Website: enter a bare domain → the preview shows https:// added; scan → the site opens
- [ ] Wi-Fi: enter your network name + password → scan with your phone camera → it offers to join the network
- [ ] Contact: fill name + phone + email → scan → the phone offers to save the contact with all fields
- [ ] Email/SMS/Phone/Location: generate each → scan → the matching app opens with fields pre-filled
- [ ] Clear a required field → Generate → the error appears under that field, nothing is generated
- [ ] Latitude 91 → range error; email without "@" → format error
- [ ] Error correction H with a long text → the "too long" message names the limit; switch to L → it generates
- [ ] PNG at 2048 and SVG downloads both save and open; SVG stays sharp when enlarged
- [ ] Narrow the window to ~380 px → layout stacks, all controls reachable
- [ ] After CMS upload, open `app.html?slug=qr-code-generator` on the live site → generate and download inside the iframe
